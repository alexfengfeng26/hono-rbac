# 通用陪玩系统 · 管理后台功能方案 v1.0

> 定位：连接「服务需求方（用户）」与「服务供给方（达人/陪玩师）」的撮合平台管理后台
> 适用范围：游戏陪玩、语音陪聊、学习辅导、健身陪练、伴游向导、技能教学等大多数「人服务人」的陪玩/陪伴类行业
> 与《游戏陪玩系统管理后台功能方案 v1.1》的关系：本方案是其抽象简化版——去游戏化、去重模块，只保留跑通业务闭环的最小核心集；游戏行业落地时可将「品类」实例化为「游戏」

---

## 一、核心领域模型

### 1.1 三类角色

| 角色 | 说明 |
| --- | --- |
| 用户（下单方） | 浏览服务、下单支付、评价 |
| 服务者（接单方） | 通过认证后发布服务、接单履约、获得收入并提现 |
| 平台（管理方） | 超管 + 子账号（绑定角色，菜单级权限控制） |

### 1.2 五个核心实体

| 实体 | 抽象自 v1.1 | 说明 |
| --- | --- | --- |
| 品类（Category） | 游戏 | 服务的行业分类，如：游戏 / 语音聊天 / 学习辅导 / 运动健身 |
| 技能等级（Level） | 游戏段位等级 | 品类下的服务能力分级，绑定价格区间与认证方式 |
| 服务（Service） | 陪玩服务 | 服务者发布的可售单元：标题 + 品类 + 等级 + 价格 + 标签 |
| 订单（Order） | 陪玩订单 | 统一订单模型，单一状态机驱动 |
| 钱包（Wallet） | 用户钱包 + 流水 | 服务者收入入账、平台分账、提现的资金载体 |

### 1.3 货币

默认**单货币（现金）**：订单支付、分账、提现全部以人民币结算。虚拟币（金币/钻石）仅在启用「虚拟礼物」扩展时才需要，作为可选配置而非默认架构。

## 二、一级菜单架构（核心 8 模块 · 15 个子页面）

```
仪表盘
用户管理
品类与等级
├─ 品类管理
└─ 技能等级配置
服务管理
├─ 服务列表
└─ 服务标签配置
订单管理
认证管理
├─ 实名认证
└─ 技能认证
财务管理
├─ 提现管理
└─ 财务流水
系统管理
├─ 系统设置
├─ 子账号管理
└─ 角色管理
```

> 对比 v1.1 的 19 个一级模块 / 43 个子页面，核心版裁剪掉：护航单、派单、游戏专属配置、页面装修、爵位、礼物、签到、工会、语音房、社区、分销、敏感词——这些全部降级为「可选扩展模块」（见第五章）。

## 三、核心功能模块明细

### 1. 仪表盘
- 4 个核心卡片：总用户数 / 总订单数 / 总订单金额（GMV）/ 订单状态分布
- 趋势图：订单量与订单金额趋势（7/30/90 天切换）
- 排行表：服务者接单排行（昵称 / 单量 / 金额 / 完成率）、热门服务排行

### 2. 用户管理
- 搜索：用户名 / 昵称 / 手机号
- 字段：ID / 头像 / 昵称 / 手机号 / 用户类型（普通·服务者）/ 实名状态 / 状态（正常·封禁）/ 余额 / 注册时间
- 行操作：查看 / 编辑 / 禁用 / 余额流水
- 批量操作：批量启用 / 批量禁用 / 导出

### 3. 品类与等级
#### 3.1 品类管理
- 新增品类 / 批量启停 / 排序
- 字段：图标 / 品类名称 / 描述 / 服务者数量 / 平台分佣比例 / 热门标记 / 状态
- 示例：游戏陪练 / 语音聊天 / 学习辅导 / 健身陪练 / 伴游向导

#### 3.2 技能等级配置
- 字段：所属品类 / 等级名称 / 等级描述 / 认证方式（上传资质·平台考核）/ 价格区间（按小时·按次）/ 排序 / 状态
- 业务：等级决定服务者的准入门槛与定价范围，是平台控价的核心抓手

### 4. 服务管理
#### 4.1 服务列表
- 搜索：服务标题 / 服务者 / 品类
- 字段：ID / 品类 / 服务标题 / 发布者 / 价格（元/小时 或 元/次）/ 评分 / 接单量 / 标签 / 状态 / 推荐 / 创建时间
- 行操作：查看 / 编辑 / 上下架 / 推荐
- 批量操作：批量推荐 / 批量上下架 / 批量删除

#### 4.2 服务标签配置
- 字段：标签名称 / 排序 / 状态
- 业务：标签用于客户端筛选与搜索曝光，平台统一维护词库

### 5. 订单管理
- 统一订单列表（全行业共用单一状态机）：
  `待接单 → 待支付 → 进行中 → 已完成`；异常分支：`已取消 / 已退款`
- 字段：订单号 / 用户信息 / 服务者信息 / 服务标题 / 品类 / 金额 / 订单状态 / 支付状态 / 创建时间
- 行操作：详情（服务记录 / 评价 / 投诉）、导出
- 底部统计：订单总数 / 待支付 / 进行中 / 已完成

### 6. 认证管理
#### 6.1 实名认证
- 字段：用户信息 / 真实姓名 / 证件号 / 证件照片 / 状态（待审核·已通过·已拒绝）/ 拒绝原因 / 提交时间
- 操作：通过 / 拒绝（可批量）

#### 6.2 技能认证
- 字段：用户 / 品类 / 认证等级 / 认证方式 / 资质材料 / 状态 / 审核结果 / 提交时间
- 操作：通过 / 拒绝 / 考核结果录入
- 业务：服务者接单前的准入门槛，可按品类配置是否需要

### 7. 财务管理
#### 7.1 提现管理
- 字段：提现 ID / 用户信息 / 提现金额 / 收款账户（脱敏）/ 状态（待审核·已通过·已打款·已拒绝）/ 申请时间
- 流程：服务者申请 → 平台审核 → 打款 → 标记已打款

#### 7.2 财务流水
- 字段：流水 ID / 用户 / 交易类型（订单支付·分账·退款·提现）/ 金额 / 交易后余额 / 关联单据 / 时间
- 支持导出

### 8. 系统管理
#### 8.1 系统设置
- 基础配置：平台名称 / 客服联系方式
- 分成配置：平台默认分成比例 %（可按品类覆盖）
- 订单配置：接单超时时间 / 自动完成时间
- 功能开关：各扩展模块的总开关（见第五章）

#### 8.2 子账号管理
- 字段：用户名 / 昵称 / 手机号 / 绑定角色 / 状态 / 最后登录
- 支持从已有用户中选择或新建

#### 8.3 角色管理
- 字段：角色名称 / 描述 / 权限分配（菜单树勾选）/ 状态
- 内置：超管

## 四、核心业务流程

### 流程 A：自主下单闭环
```
用户浏览服务 → 下单 → 待支付
   ↓ 支付
待接单 → 服务者接单 → 进行中 → 已完成 → 自动分账（平台抽成 + 服务者入账）
   ↓ 超时未接单
自动取消 → 原路退款 → 流水记入
```

### 流程 B：认证与提现闭环
```
服务者提交实名 + 技能认证 → 平台审核 → 获得接单资格
   ↓ 履约产生收入
收入入账（扣除平台分成）→ 申请提现 → 平台审核 → 打款 → 流水闭环
```

> v1.1 中的护航单（配单/补单/手动分账）、派单、试音等重型流程不属于通用核心，归入扩展模块或行业定制。

## 五、可选扩展模块（按需启用）

| 扩展模块 | 用途 | 包含子页面 | 依赖 |
| --- | --- | --- | --- |
| 分销推广 | 老客拉新、服务返佣 | 分销员管理 / 分销记录 / 邀请记录 | 订单、财务 |
| 社区动态 | 内容互动、提升留存 | 动态管理 / 违规处理 / 敏感词管理 | 用户 |
| 虚拟礼物 | 打赏创收（需开启虚拟货币） | 礼物分类 / 礼物管理 / 送礼记录 | 钱包、系统设置 |
| 会员订阅 | 付费会员权益（由爵位系统简化） | 会员等级 / 会员订单 / 权益配置 | 用户、财务 |
| 语音房 | 实时语音互动场景（试音厅/音乐厅合并抽象为"互动房间"） | 房间管理 / 类型配置 / 标签管理 | 用户、礼物（可选） |
| 机构入驻 | MCN/工作室/公会形态的组织管理 | 入驻申请 / 机构列表 | 用户、财务 |

启用方式：系统设置中的功能开关统一控制，未启用的模块不出现在菜单中。

## 六、行业裁剪建议

| 行业 | 品类实例化 | 建议启用扩展 | 建议关闭 |
| --- | --- | --- | --- |
| 游戏陪玩 | 游戏 + 段位等级 | 分销、语音房、礼物、会员 | — |
| 语音陪聊 | 聊天主题 + 声音标签 | 语音房、礼物、会员 | 技能认证可简化为资料审核 |
| 学习辅导 | 学科 + 难度等级 | 分销 | 语音房、礼物 |
| 健身/运动陪练 | 项目 + 教练等级 | 机构入驻 | 语音房、礼物、会员 |
| 伴游/向导 | 目的地 + 服务类型 | 机构入驻 | 语音房、礼物、分销 |

**MVP 建议**：仅交付第二章 8 个核心模块即可上线运营；扩展模块按行业与运营阶段逐个开启，避免一次性建设 43 个页面的重型后台。

## 七、关键设计原则

1. **统一优先**：订单只有一套状态机；认证两条审批流共用一套审核交互；扩展房间统一抽象为"互动房间"
2. **配置驱动**：品类、等级、标签、分成比例、功能开关全部后台可配，行业差异通过配置而非定制代码解决
3. **单货币起步**：现金流是刚需，虚拟币是增值；架构预留但不默认建设
4. **轻准入、重结算**：服务者准入流程尽量短（实名 + 技能两级），资金侧（分账、提现、流水）保持完整闭环
